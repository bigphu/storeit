## Environment files

| File | For |
|---|---|
| `.env` | Docker Compose: ports, admin account, seed password, JWT settings. Created by `make init` from `.env.example` |
| `backend/.env.local` | Environment for running Go on the host; paths point into `deploy/` |
| `.env.prod.example` | Template for production: image names, `APP_URL`, `MAIL_FROM` |

Common settings in `.env`: `WEB_PORT`, `APP_PORT`, `PG_PORT`, `PGADMIN_PORT`, `MAILPIT_PORT`, `APP_DB_NAME`,
`APP_DB_USER`, `JWT_ACTIVE_KID`, `JWT_ISSUER`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `SEED_PASSWORD`.

Secrets and certificates are generated by `sh deploy/scripts/init.sh` into `deploy/` and are git-ignored.

## Daily commands

| Command | Does |
|---|---|
| `make init` | Once: secrets, TLS certificates, `.env`, `backend/.env.local` |
| `make dev` | Build and start everything, follow logs |
| `make up`, `make down` | Start and stop the stack |
| `make logs-app`, `make logs-web` | Follow one service |
| `make psql`, `make pgadmin` | Database shell and admin UI |
| `make seed` | Demo data into an empty database |
| `make db-reset CONFIRM=yes` | Wipe and recreate the development database |
| `make generate` | Backend code (sqlc, oapi-codegen) and frontend API types |
| `make check` | Everything CI runs |

Never edit `*.gen.go`, `events/db` or the generated `frontend/src/lib/api/*.d.ts`; regenerate them.

## Checks

- Backend, in `backend/`: `make test`, and `make check` (sqlc compile, format, vet, lint, tests).
  `CI=true go test -p 1 ./...` runs the Docker-backed tests without skipping; `-p 1` avoids starting many test
  containers at once, which can fail on Windows.
- Frontend, in `frontend/`: `npm run check` (type check, Vitest, build). `npm run dev` serves on port 3000 and
  proxies `/api` to 8080; stop the `web` container first.
- GitHub Actions workflows exist for the backend and the frontend.

## Production

The live site is https://storeit.bigphu.io.vn. Releases follow
[Shipping features and migrations](/guides/deploying/).

First setup of a server:

1. Clone the repository to `/opt/storeit` and check out the release tag.
2. `sh deploy/scripts/init.sh` for new secrets and certificates (never copy them from a dev machine).
3. Copy `.env.prod.example` to `.env` and set `APP_URL`, `MAIL_FROM`, `MAIL_TRANSPORT` and, for the first start
   only, `ADMIN_EMAIL` and `ADMIN_PASSWORD`.
4. `make images TAG=<tag>` builds `storeit/storeit:<tag>` and `storeit/storeit-web:<tag>` on the server; set
   `STOREIT_IMAGE` and `STOREIT_WEB_IMAGE` in `.env` to them.
5. `docker compose -f compose.prod.yml up -d`.

Only the `web` container publishes a port, on `127.0.0.1:${WEB_PORT}`. Host nginx terminates HTTPS in front of it:
`deploy/nginx/storeit.bigphu.io.vn.conf` is the site file (Let's Encrypt certificates through certbot's
Cloudflare DNS plugin, because the provider blocks inbound traffic from abroad).

Production mail goes through Resend. The provider blocks outbound SMTP ports, so the server uses Resend's HTTPS
API: `MAIL_TRANSPORT=resend`, with the API key in `deploy/app/secrets/smtp_password.txt`. The worker refuses to
start while that file is empty.
