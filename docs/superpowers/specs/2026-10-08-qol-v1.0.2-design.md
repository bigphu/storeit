# Quality-of-life release v1.0.2 — design

Date: 2026-10-08. Status: approved in conversation. Branch `feat/qol-v1.0.2`, from `main` at `v1.0.1`.

## Goal

Make the app faster to drive from the keyboard. Make exports usable without manual fixing. Let users filter assets by the fields every asset has.

The release covers twelve changes, grouped into five areas:
- **A. Keyboard:** page keys, quick-edit keys, more shortcuts (including Shift + mouse wheel for sideways scrolling), hints on buttons, a better help dialog.
- **B. Tabs:** an empty work area when every tab is closed.
- **C. Export:** "one sheet per type" as the default report layout, a Columns editor that follows the preview tab, and auto-fitted column widths.
- **D. Built-in field filters:** a new API parameter and a "Built-in" group in the filter popover.
- **E. List polish:** `=` instead of "is" in filter labels, and the asset table keeps its scroll position when the page changes.

Out of scope:
- custom shortcuts;
- filtering custom attributes across types;
- location and holder filters (their directory does not exist yet);
- auto-fitting columns from every row of a large export.

## A. Keyboard

### One shortcut registry

A new module `frontend/src/lib/shortcuts.ts` lists every shortcut once:

```ts
export type ShortcutGroup = 'Anywhere' | 'Lists' | 'Asset page' | 'Quick edit' | 'Forms'
export interface Shortcut { keys: string; action: string; group: ShortcutGroup }
export const SHORTCUTS: readonly Shortcut[]
export function shortcutGroups(): { group: ShortcutGroup; items: Shortcut[] }[]  // in the order above
```

The help dialog and the button hints both read from it, so the text and the keys cannot drift apart.

| Group | Keys | Action | Status |
|---|---|---|---|
| Anywhere | `?` | Show keyboard shortcuts | existing |
| Anywhere | `Ctrl K` | Go to an asset type (keeps the section you are in) | existing |
| Anywhere | `Alt 1–9` | Go to tab 1–9 | existing |
| Anywhere | `Ctrl Z` | Undo the change in the latest message | existing |
| Anywhere | `Ctrl-click`, `middle-click` | Open a link in a new tab | existing |
| Anywhere | `Esc` | Close a dialog, menu or drawer | existing |
| Lists | `J` / `K` | Previous / next page | new |
| Lists | `/` | Search the list | extended to every list with a search box |
| Lists | `N` | New item (asset, type, role, export profile, or invite an account) | extended to every list with a create button |
| Lists | `F` | Add a filter (asset list) | new |
| Lists | `Shift` + mouse wheel | Scroll a wide table sideways | new (documents the browser's own behaviour) |
| Asset page | `J` / `K` | Previous / next asset | existing |
| Asset page | `E` | Edit the asset | existing |
| Quick edit | `J` / `K` | Previous / next row | changed: replaces ↑ / ↓ |
| Quick edit | `Ctrl S` | Save | existing |
| Quick edit | `Ctrl Enter` | Save, then open the next row | new |
| Forms | `Ctrl S` | Save | existing, now listed |

### How the keys behave

1. **List keys.** `J`, `K`, `/`, `N` and `F` use `usePageKeys`. They do nothing while the user is typing in a field, while Ctrl, Alt or ⌘ is held, while a dialog or menu is open, or while the page sits in a background tab.
2. **`J` / `K` paging.** These page through the Assets and Accounts tables. On the first or last page the key does nothing.
3. **`N`.** It acts only when the user has the permission that shows the create button.
4. **`/`.** It focuses the list's search box and calls `preventDefault`, so the `/` is not typed into the box.
5. **`F`.** It opens the filter popover, anchored to the "Add filter" button.
6. **Quick edit.** `QuickEditDrawer` swaps `ArrowDown` / `ArrowUp` for `k` / `j`. The existing check stays: keys are ignored when focus is in an input, textarea, select, contenteditable element, select overlay or date panel. `Ctrl Enter` saves only when the drawer has unsaved changes and isn't busy, then moves to the next row. If nothing changed, it just moves to the next row.
7. **Hint text.** The quick-edit drawer's hint now reads "J / K moves to the previous or next row. Ctrl Enter saves and moves on."

### Hints on buttons

A new component, `frontend/src/components/KeyHint.vue`, renders one key cap: `<kbd class="key-hint">N</kbd>`. Its text is the muted text colour. It has a 1 px border in the divider colour and is `aria-hidden="true"`, because the button's accessible name already includes the key.

- **Buttons with a label:** the key cap goes after the label, inside the button's default slot, e.g. "New asset `N`".
- **Icon-only buttons:** the key goes into the tooltip and `aria-label` instead, e.g. "Next page (K)", "Edit (E)".
- **Touch screens:** key caps are hidden under `@media (hover: none)`.

Buttons that get a hint:
- the create button on Assets, Asset types, Roles, Export profiles and Accounts;
- Edit on the asset page;
- the previous / next asset steppers;
- the quick-edit drawer's previous / next and Save buttons.

The paginator's own icon buttons are PrimeVue internals. They get no hint; the help dialog covers them.

### Help dialog

The `?` dialog in `AppLayout.vue` becomes a PrimeVue `DataTable` with one row per shortcut, grouped with row-group headers in the registry's group order:
- two columns: Keys (each key in its own `<kbd>`) and Action;
- dividers between rows, from the table's own row borders;
- no hover tint;
- width `min(92vw, 36rem)`;
- it scrolls inside the dialog when taller than the window.

## B. Tabs: empty work area

Today, closing the last tab opens `/assets`. Pinned tabs can't be closed, so the tab list only becomes empty after the user unpins "All assets" and closes everything.

After this change:

1. **A new route.** `/empty`, with `meta: { tab: false, title: 'No open tabs' }`. `syncPath` ignores routes with `tab: false`, so `/empty` never becomes a tab.
2. **What `close` does.** When `close` in `useTabs.ts` leaves no tabs, it sets `activeId` to `null` and calls `router.replace('/empty')`.
3. **What the work area shows.** While the tab list is empty, `AppLayout` renders an `EmptyState` in place of the `RouterView`: icon `pi pi-clone`, "No open tabs", "Open a page from the sidebar or press Ctrl K." The sidebar, header and empty tab bar stay.
4. **Opening the next page.** Any navigation to a page other than `/empty` runs `syncPath` with no active tab, which already creates and activates a tab.
5. **`/empty` while tabs exist.** For example, after a reload that restored tabs, or the browser's Back button. A `beforeEnter` guard redirects to the first tab's path.
6. **`/` is unchanged.** It still redirects to `/assets`, so first-time visitors and sign-in land on the asset list.
7. **Undo.** Undo of the last close works as before: `reopen` adds the tab back and activates it.
8. **Saved tabs.** The saved tab list is empty, and `seeded` is already true, so a reload at `/empty` shows the empty state.

## C. Export

### Default layout

`defaultReportLayout()` in `frontend/src/features/assets/export/layout.ts` returns `sheets: 'per_type'`. Saved profiles and the data export are unchanged. The report dialog's preview already handles `per_type`.

### Column editor follows the preview tab

In the report dialog, the preview at the right shows one tab per sheet. With "One sheet per type", each type's sheet already shows only the columns that apply to it (`sheetColumns`). The Columns editor at the left still lists every field of every type. After this change, the editor lists only the rows for the sheet that is open in the preview:

1. **Which tab is open.** `SheetPreview` exposes its open tab through `v-model:active` (sheet index). `ReportEditor` holds it and passes the open sheet's types to `ColumnEditor` as `scopeTypes: TypeInfo[] | null`.
2. **What the editor shows.**
   - **On a type's sheet:** `scopeTypes` is that one type. The editor shows the built-in fields (tag, name, type, status, purchase date, …) plus that type's attributes, ticked or not.
   - **On the single sheet** (named after the export scope, e.g. "All assets") **or the Summary tab:** `scopeTypes` is `null`, and the editor shows every row, as today.
   - **The rule** lives in `layout.ts`: `editorRowsFor(cols, scopeTypes): EditorColumn[]`. A row shows when its field is not an attribute, or when its attribute key belongs to one of `scopeTypes`.
3. **Edits still apply to the whole report.** The layout has one column list shared by every sheet, so ticking, renaming, setting a width or reordering a row changes it for every sheet where it applies. A note above the list says so: "Showing the columns of the Laptop sheet. Changes apply to every sheet that has them." The "Columns N" count on the tab stays the report's total.
4. **Reordering while filtered.** Dragging a row among the visible rows reorders only those rows. Hidden rows keep their positions: the visible rows' new order fills the slots the visible rows held before. The rule lives in `layout.ts`: `reorderVisible(all, visible, from, to): EditorColumn[]`.
5. **When the open sheet disappears.** For example, after switching to a single sheet, or when the filters remove a type. The preview falls back to its first tab, as today, and the editor follows it.

### Auto-fitted column widths

The spreadsheet writer streams rows, and excelize needs every column width before the first row. So:

1. **New options.** `spreadsheet.SheetOptions` gets `AutoWidth bool`. `Sheet()` no longer writes widths and panes straight away when `AutoWidth` is set. It buffers rows until `autoWidthSample` rows (500) have arrived, or `Close` is called.
2. **Widths.** For each column, the width is the largest of:
   - the header length + 4 (for the filter button);
   - the longest display length + 2 among the buffered cells.
   The result is clamped to 10 to 60 characters.
3. **Display length.** Text uses its rune count; for multi-line text, the longest line. A number uses the length of its formatted value (`strconv.FormatFloat(v, 'f', -1, 64)`, plus the unit when the layout puts units in cells). A date uses the length of its `NumFmt` pattern. A boolean uses the length of its rendered label.
4. **Writing.** Then the writer sets the widths, freeze panes, title rows and header row, flushes the buffered rows, and streams the rest. Memory stays bounded by 500 rows.
5. **What still wins.** A column with an explicit `width` in the profile keeps that width. The summary sheet keeps its fixed widths.
6. **Where it's on.** `service/export.go` sets `AutoWidth: true` for report and data exports.

## D. Built-in field filters

### API

`GET /assets` and the export request's filters get a repeated query / body parameter `field`, shaped `<key>:<op>:<value>`, the same shape as `attr`. It works with or without `type_id`.

| Key | Data type | Operators | Value |
|---|---|---|---|
| `purchase_date` | date | `eq`, `gt`, `gte`, `lt`, `lte` | `YYYY-MM-DD` |
| `created_at` | date (day) | `eq`, `gt`, `gte`, `lt`, `lte` | `YYYY-MM-DD` |
| `updated_at` | date (day) | `eq`, `gt`, `gte`, `lt`, `lte` | `YYYY-MM-DD` |
| `description` | text | `contains` | 1–200 characters |

- **Timezone parameter.** A new optional `tz` query parameter (IANA name, default UTC) tells the server which calendar day `created_at` and `updated_at` belong to. The frontend always sends the browser's zone. Export already takes `time_zone`, and its filters reuse that value.
- **Validation.** `domain.ResolveFieldQuery(conds []string) ([]FieldFilter, error)` validates and parses. Errors are `422` with field errors `field[i]`: unknown key, an operator not allowed for the key, a bad date, or empty or too-long text.
- **Day boundaries.** `FieldFilter{Field, Op, Value}` carries day-based comparisons already turned into instants. For `created_at` and `updated_at`, `eq` becomes `>= start of day AND < start of next day`, and `gt` becomes `>= start of next day`. The service does this conversion with the zone from `tz`, so SQL only compares timestamps.

### SQL

`ListAssets` and `CountAssets` in `repository/queries/assets.sql` get three parallel arrays, `b_fields`, `b_ops` and `b_vals`. Like the attribute filters, every condition `i` must hold:

```sql
AND NOT EXISTS (
  SELECT 1 FROM generate_subscripts(@b_ops::text[], 1) AS b(i)
  WHERE NOT (CASE (@b_fields::text[])[b.i] || '_' || (@b_ops::text[])[b.i]
    WHEN 'purchase_date_eq'  THEN a.purchase_date =  (@b_vals::text[])[b.i]::date
    WHEN 'purchase_date_gt'  THEN a.purchase_date >  (@b_vals::text[])[b.i]::date
    -- … gte, lt, lte
    WHEN 'created_at_gte'    THEN a.created_at  >= (@b_vals::text[])[b.i]::timestamptz
    WHEN 'created_at_lt'     THEN a.created_at  <  (@b_vals::text[])[b.i]::timestamptz
    -- updated_at the same; the service only ever sends gte / lt for timestamps
    WHEN 'description_contains' THEN a.description ILIKE '%' || (@b_vals::text[])[b.i] || '%'
    ELSE false END)
)
```

- **No `NULL` matches.** An asset with no purchase date never matches a `purchase_date` condition.
- **No migration.** The query uses existing columns. `make generate` regenerates sqlc and the OpenAPI types.

### Export

- **Filters.** `ExportFilters` gets `field []string`. The service resolves it the same way.
- **Description of the filters.** `filterRecord` (the export history) and `exportTitle` (the optional title row) include the filters, e.g. "Purchase date ≥ 01/01/2026".

### Frontend

1. **List state.** `AssetListState` gets `fields: FieldFilterRow[]`, stored in the URL as repeated `field=` values. `toApiParams` sends them with `tz`. `parseAssetQuery` drops malformed values.
2. **Filter popover.** `AttributeFilterPopover` lists a "Built-in" group (Purchase date, Created, Updated, Description) above the type's attributes. Under "All assets" it shows the "Built-in" group only. The operator and value inputs reuse the existing date and text editors.
3. **Chips.** Filter chips label built-in conditions the same way as attributes: "Purchase date ≥ 01/01/2026", "Description contains dock". Removing a chip, "Clear filters" and changing type all behave as they do for attribute chips. The difference: changing type keeps built-in filters, because they apply to every type.

## E. List polish

### "=" instead of "is"

In `features/assets/filterChips.ts`, `OP_LABEL.eq` becomes `=` and `OP_LABEL.in` becomes `any of`. Chips, tab titles and the popover's operator list all read this map. Examples: "RAM = 16 GB", "OS any of Windows, macOS". The status and search chips keep their "Status: Available" form.

### Keep the scroll position when changing pages

When the asset table changes page (paginator, page-size change excluded, or `J` / `K`):
- the content area keeps its vertical scroll;
- the table's horizontal scroll stays where it was.

`AssetsPage` records both positions before calling `update({ page })`:
- the work area's `scrollTop`;
- the table wrapper's `scrollLeft` (`.p-datatable-table-container`).

It puts them back after the new page's rows have rendered (`watch` on the list data, then `nextTick`). If the new page is shorter, the browser clamps the vertical position.

The cause (PrimeVue's scrollable table resetting its container, or the work area jumping) is confirmed in the browser before fixing. The fix restores both positions either way. Accounts uses the same paging, so it gets the same treatment through a small helper in `lib/tableRows.ts`:

```ts
useKeepScrollOnPage(tableRoot: Ref<HTMLElement | undefined>, data: Ref<unknown>): { beforePageChange(): void }
```

## Testing

### Frontend (Vitest)
- `shortcuts.ts`: every group is non-empty, groups come in the declared order, and no key is listed twice within a group.
- Paging keys: `J` on page 1 does nothing; `K` on the last page does nothing; both are ignored while typing.
- Quick edit: `j` and `k` emit prev and next; arrows no longer do; keys are ignored inside an input; `Ctrl Enter` saves when dirty and otherwise only moves on.
- `useTabs`: closing the last tab leaves zero tabs and routes to `/empty`; `/empty` creates no tab; the next navigation creates a tab; Undo reopens the tab; `/empty` with tabs present redirects to the first tab.
- `defaultReportLayout().sheets === 'per_type'`.
- `editorRowsFor`: built-in fields are always shown, attributes only for `scopeTypes`, and `null` shows everything. `reorderVisible`: hidden rows keep their positions, and visible rows take the new order.
- `listQuery`: `field` round-trips through the URL, and malformed values are dropped. `toApiParams` sends `field` and `tz`.
- `filterChips`: `=` and `any of` labels; built-in chips; changing type keeps built-in filters.
- `useKeepScrollOnPage`: restores `scrollTop` and `scrollLeft` after the data changes.

### Backend
- `domain.ResolveFieldQuery`: every key and operator pair; unknown key, wrong operator, bad date and long text each give a `field[i]` error; day boundaries for `eq` and `gt` in `Asia/Ho_Chi_Minh` and UTC.
- Repository tests against a real database: each field and operator against seeded assets, including a `NULL` purchase date, combined with `attr` and `type_id`, and the counts matching the list.
- HTTP: `field` without `type_id` returns `200`; a bad `tz` returns `422`.
- Spreadsheet writer:
  - widths from the header vs. from long cells;
  - the 10 and 60 clamps;
  - multi-line text;
  - an explicit width winning;
  - a sheet with fewer than 500 rows (flushed on `Close`);
  - a sheet with more than 500 rows (rows after the sample still written in order).
- Export: `field` filters narrow the exported rows, and the title row names them.

### Manual (browser)
- Asset list: change page with the paginator and with `K` while scrolled down and sideways; the view stays put.
- Closing every tab shows the empty state; the sidebar opens a new tab.
- The `?` dialog shows the grouped table.
- An exported report opens with one sheet per type and readable column widths.
- Report dialog: switching preview tabs changes the Columns list; the single "All assets" sheet and the Summary tab show every column.
